# TypeScript 5.x

本文件适用于 **5.x**。不要用 6.0 才有的：`es2025` `target`/`lib`、`Temporal` 内置类型、`Map.getOrInsert`、`#/` subpath、`stableTypeOrdering`、6.0 新默认（`types: []`、`rootDir: ./`、默认 `strict`）。不要用 7.0 的原生 `tsc`、`--checkers`、模板字面量按 Unicode 码点切分。

项目 minor 为 `5.y` 时，只用 **5.0 … 5.y** 小节。更高 minor 的语法、flag、lib 一律禁止。

## 5.0

标准 decorators（默认语法，不要 `experimentalDecorators`）：

```ts
function logged(fn: Function, _ctx: ClassMethodDecoratorContext) {
  return function (this: unknown, ...args: unknown[]) {
    return fn.apply(this, args)
  }
}
class C {
  @logged
  m() {}
}
```

`const` 泛型：约束用 `readonly`，否则会退回宽类型。

```ts
function ids<const T extends readonly string[]>(xs: T): T {
  return xs
}
ids(["a", "b"]) // readonly ["a", "b"]
```

- `moduleResolution: "bundler"` 只能配 `"module": "esnext"`（库发 npm 用 `node16`/`nodenext`）。
- `verbatimModuleSyntax`：无 `type` 的 import/export 原样保留。`export type * from "./t"` 只导出类型。
- `allowImportingTsExtensions` 仅在 `noEmit` 或 `emitDeclarationOnly` 下合法。

## 5.1

getter / setter 类型可以完全无关，但必须显式注解：

```ts
interface Box {
  get value(): string
  set value(v: string | number)
}
```

声明返回 `undefined` 的函数可以没有 `return`。

## 5.2

资源用 `using` / `await using`，不要手写 try/finally。实现 `Disposable` / `AsyncDisposable`（`[Symbol.dispose]` / `[Symbol.asyncDispose]`）。多资源用 `DisposableStack` / `AsyncDisposableStack`。

```ts
using file = openTemp()
await using db = await connect()
```

`module Foo {}` 已 emit 成 `namespace`。新代码写 `namespace`；`declare module "x"` 仍是合法的模块声明。

## 5.3

JSON / 自定义加载用 import attributes，不要 `assert`：

```ts
import data from "./data.json" with { type: "json" }
await import("./data.json", { with: { type: "json" } })
```

`switch (true)` 的 `case` 会收窄。`import type` 可用 `resolution-mode`。

## 5.4

推理不要被默认参数带偏时，包 `NoInfer<T>`：

```ts
function create<C extends string>(colors: C[], fallback?: NoInfer<C>) {}
```

`Object.groupBy` / `Map.groupBy` 只有运行时存在才用（类型在 5.4 已进 lib；`target es2024` 是 5.7）。返回对象的键是可选的。

`"module": "preserve"` + `"moduleResolution": "bundler"` 允许 `require()`。

## 5.5

`filter` 等会**推断** type predicate。不要给 number 写 `!!x`（`0` 会被滤掉且不会当 predicate）。显式 `x is T` 仍可用，但不比 `as` 更安全。

```ts
const nums = xs.filter((x): x is number => typeof x === "number")
const present = items.filter(x => x !== undefined)
```

发 `.d.ts` 且要并行 emit：开 `isolatedDeclarations`（须 `declaration` 或 `composite`）。导出函数写明返回类型。业务 app 不必开。

`Set` 的 `union` / `intersection` / `difference` / `symmetricDifference` / `isSubsetOf` 等：有运行时再用。

## 5.6

iterator helpers 已进类型。`Iterator` 仍是协议；带 `map`/`filter`/`take` 的运行时对象是 `IteratorObject`（以及 `ArrayIterator` / `MapIterator` / `SetIterator`）。

```ts
for (const n of ints().map(x => x * 2).take(5)) {}
Iterator.from(iterable).filter(pred)
```

- 语法上恒 truthy / 恒非 nullish 的条件会报错（`if (/re/)`、`a < b ?? 1`）。
- 建议开 `noUncheckedSideEffectImports`：找不到文件的 `import "x"` 不再静默。资源文件写 `declare module "*.css" {}`。6.0 起默认开。

## 5.7

从未赋值的变量，嵌套函数里也会报「使用前未赋值」。可能被赋值的分支仍宽松。

相对路径且以 `.ts` / `.tsx` / `.mts` / `.cts` 结尾：需要 emit JS 时开 `rewriteRelativeImportExtensions`（改写成 `.js` 等）。`paths`、包名、`#` subpath **不会**改写。如何用 Node 直接跑 `.ts` 见 node 技能。

`target` / `lib` 可用 `es2024`（`Object.groupBy`、`Promise.withResolvers`、`TypedArray` 带 `TArrayBuffer`）。`nodenext` 下 JSON 必须 `with { type: "json" }`，且只能走 default import。

## 5.8

Node type stripping / `erasableSyntaxOnly`：禁止有运行时语义的 TS 语法——`enum`、带值的 `namespace`、构造器参数属性、`import =`。通常与 `verbatimModuleSyntax` 一起开。跑 `.ts` 的方式见 node 技能。

`libReplacement`：不用 `@typescript/lib-*` 就设 `false`（6.0 起默认 `false`）。要用自定义 lib 显式 `true`。

`require(esm)`：**仅** `"module": "nodenext"` 允许。`node18` **禁止** `require(esm)`，且仍允许 import `assert`。`nodenext` 下 `assert` 报错，必须 `with`。

## 5.9

`import defer` 只允许命名空间形式，且**不降编译**；仅 `"module": "preserve"` | `"esnext"`，运行时或 bundler 必须认识它。

```ts
import defer * as feature from "./feature.js"
feature.specialConstant // 此刻才执行模块
```

`"module": "node20"`：钉 Node 20（隐含 `target es2023`）。允许 `require(esm)` 与 `with`，禁止 `assert`。跟踪最新 Node 仍用 `nodenext`（隐含 `target esnext`）。

`tsc --init` 生成更短的 tsconfig（含 `"types": []`）。这是脚手架，**不是** 5.9 编译器默认；默认 `types` 变 `[]` 从 6.0 才生效。
