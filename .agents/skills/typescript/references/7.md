# TypeScript 7.x

本文件适用于 **7.x**。6.0 弃用项在此是硬错误；`ignoreDeprecations` 无效。类型检查语义与「开了 `stableTypeOrdering`、且未设 `ignoreDeprecations`」的 6.0 对齐。

## 类型检查入口

跟项目已有的 typecheck / 编译命令，不要默认改成 `npx tsc`。项目已有的 oxc / 基于 tsc 的检查器都算合法入口；语言规则与 `tsconfig` 仍按本档。

已安装的 `typescript` 是 7 时：编译器是 Go 实现（约 8–12×）。**7.0 无稳定 programmatic API**，不要 `import ts from "typescript"`。需要 API 的工具（typescript-eslint 等）用 `@typescript/typescript6` / npm alias；应用侧语言行为以 7 为准：

```json
{
  "devDependencies": {
    "@typescript/native": "npm:typescript@^7.0.2",
    "typescript": "npm:@typescript/typescript6@^6.0.2"
  }
}
```

只装 7：`npm i -D typescript@7`。不要再装 `@typescript/native-preview`（nightly 回到 `typescript@next`）。

## 默认（继承 6.0，7 再加一条）

- `strict`: `true`
- `module`: `esnext`
- `target`: `esnext` 的前一个稳定 ES
- `noUncheckedSideEffectImports`: `true`
- `libReplacement`: `false`
- `types`: `[]`（恢复旧行为才 `"types": ["*"]`；Node 写 `["node"]`）
- `rootDir`: `./`（源码在 `src/` 就写 `"rootDir": "./src"`）
- `stableTypeOrdering`: `true` 且**不可关**

## 硬错误（6 的弃用在此无退路）

禁止：`target: es5`、`downlevelIteration`、`baseUrl`、`moduleResolution: node10`/`node`/`classic`、`module` 为 `amd`/`umd`/`system`（`systemjs`）/`none`、`esModuleInterop: false`、`allowSyntheticDefaultImports: false`、`alwaysStrict: false`、`outFile`、`module Foo {}` 当 namespace、import `assert`、`no-default-lib` 指令。

用 `tsc` 且已有 tsconfig 时，命令行再传文件路径会报错，除非 `--ignoreConfig`。

## 模板字面量类型

按 Unicode **码点**切分，不要再写 UTF-16 surrogate 的 `Head`/`Tail`：

```ts
type HeadTail<S> = S extends `${infer H}${infer T}` ? [H, T] : never
type R = HeadTail<"😀abc"> // 7: ["😀", "abc"]；以前是两个 surrogate
```

## 并行与 CI

用 TypeScript 7 的 `tsc` 时：默认 `--checkers 4`。CI 小机器降 checkers（可 `--checkers 1`），不要复制博客里的 `--checkers 8`。`--builders` 管 project references 的并行；与 checkers **相乘**（`4×4` = 最多 16 个 checker）。调试或极小机器用 `--singleThreaded`。项目走其它检查入口时，按其已有并行/CI 配置，不要套这些 flag。

## Vue / 嵌入语言

Vue、MDX、Astro、Svelte、Angular 模板等仍可能停在 6（Volar / vue-tsc 依赖 API）。**应用侧检查可 7，编辑器插件不要硬切。** VS Code 可关 TypeScript 7 Language Server。不要把同一个 `typescript` 依赖硬升导致 vue-tsc 挂掉。

JS 文件：JSDoc 更靠拢 `.ts`。不要用值当类型（写 `typeof v`）、不要靠 `@enum` / `@class` / 后缀 `!` / Closure 的 `function(string): void`。

## 5.x / 6.x 仍该用（SKILL + 本档即可）

细节在旧档，缺例子再打开。不要退回这些之前的写法。

| 特性 | 自 |
| --- | --- |
| `satisfies`；`const` 泛型；标准 decorators | 5.0 |
| `verbatimModuleSyntax` + `import type`；`export type *` | 5.0 |
| `bundler` 或 Node 的 `nodenext`/`node20`/`node18`（按运行时） | 5.0 / 5.8 / 5.9 |
| getter/setter 可无关类型（显式注解） | 5.1 |
| `using` / `await using` / `DisposableStack` | 5.2 |
| import attributes `with`，不要 `assert` | 5.3 |
| `NoInfer<T>`；`Object.groupBy`（有运行时才用） | 5.4 |
| 推断 type predicate；库的 `isolatedDeclarations` | 5.5 |
| iterator helpers / `IteratorObject`；`noUncheckedSideEffectImports` | 5.6 |
| 未初始化变量检查；`rewriteRelativeImportExtensions`；`es2024` | 5.7 |
| `erasableSyntaxOnly`（配合 Node type stripping，跑法见 node 技能） | 5.8 |
| `import defer * as ns`（仅 `preserve`/`esnext`） | 5.9 |
| `es2025`：`Promise.try`、`RegExp.escape`、`Iterator`/`Set` 方法 | 6.0 |
| `Temporal`、`Map.getOrInsert`：有运行时再用 | 6.0 |
| `package.json` `"imports"` 的 `#/` | 6.0 |
| 没用 `this` 的 method，推断按箭头同样处理 | 6.0 |
